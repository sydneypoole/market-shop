# 微信注册资料与后台会员展示审计（最终结论更新于 2026-08-13）

## 已确认能力边界

- `jscode2session` 只返回身份数据，不返回头像、昵称或手机号。
- 真实头像和昵称只能由用户后续主动选择/输入，不能从 OpenID 静默反查，也不能把平台默认值表述成微信资料。
- 手机号需要独立授权能力；本产品最终确认注册不需要手机号。

## 最终注册契约

1. 普通注册页只显示邀请码和“一键注册”按钮；每次通过本地非空校验的点击取得 fresh `wx.login` code，严格提交 `{code, inviteCode}`，由后端判定邀请码有效性。
2. 显式 sponsor 模式严格提交 `{code, sponsorClaimSecret}`；普通邀请 UI 不显示模式切换，密钥不进入 URL。
3. 后端在本地事务中用数据库唯一的完整 `publicId` 生成 `宏杉会员-{publicId}` 平台昵称，保持 `avatarUrl=null`，并原子创建身份、UnionID、直属关系、会员/积分账户及邀请码计数。
4. 注册不调用或接收手机号、头像、昵称字段。失败保留邀请凭据但不用旧 login code；重试 fresh code。已有身份幂等返回，不重复邀请码计数或覆盖资料。
5. 注册和登录成功均直接首页。资料编辑仅为“我的”中的可选入口；后台显示权威平台昵称，空头像使用昵称首字降级。
6. 历史会员资料/手机号 API 可继续兼容旧账户，但不属于注册链路。

## 关键测试

- 小程序：普通 UI 仅一个邀请输入与一个主按钮、无注册资料能力、fresh code、防重复提交、失败保留邀请、成功首页、显式 sponsor 模式。
- 后端：严格 JSON shape、缺失/冲突凭据、平台昵称完整 publicId 映射、空头像、单事务图谱、既有身份幂等、身份竞态稳定冲突、发起人审计。
- 后台/个人中心：nullable avatar、昵称首字 fallback、用户后续可选昵称/头像编辑不回归。

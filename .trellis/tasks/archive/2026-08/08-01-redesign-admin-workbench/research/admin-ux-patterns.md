# 后台运营工作台交互模式研究

## 调研目标

为商城后台的导航、列表、详情、表单、批量操作和危险确认建立一致模式；本次只提炼交互原则，不引入 React/Ant Design 依赖。

## 一手资料

1. [Ant Design：数据展示](https://ant.design/docs/spec/data-display-cn/)
   - 信息顺序应由重要程度、操作频率和关联程度决定。
   - 结构化运营数据适合使用表格，并与搜索、筛选、分页组合；时间、状态和操作列应保持完整。
2. [Ant Design：列表页](https://ant.design/docs/spec/research-list/)
   - 列表页的核心目标是可扫描、可查找并可进入完整详情。
   - 高频搜索应提高操作效率；批量操作应与当前选择建立明确上下文。
3. [Ant Design：详情页](https://ant.design/docs/spec/detail-page/)
   - 详情应按接近性分组，尽量平铺关键上下文，减少无必要折叠。
   - 审核类对象适合将对象资料、流程信息和审批操作放在同一详情结构中。
4. [Ant Design：抽屉](https://ant.design/components/drawer/)
   - 抽屉适合在不离开列表上下文时查看资料、完成编辑或处理子任务。
   - 加载态应使用结构占位；提交操作固定在标题或底部操作区。
5. [Ant Design：数据录入](https://ant.design/docs/spec/data-entry-cn/)
   - 字段必须有明确标签、格式说明和上下文默认值，不能让运营人员在空白输入框中猜测。
   - 上传应展示格式、大小和进度约束。
6. [Ant Design：表单页](https://ant.design/docs/spec/research-form/)
   - 7 个以内字段可保持单组，7–15 个字段应分组，更多字段使用标签页等层次组织。
7. [Ant Design：导航](https://ant.design/docs/spec/research-navigation/)
   - 信息架构应尽量浅、平、宽，并按用户任务路径而不是代码模块组织。
8. [W3C WAI-ARIA：模态对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)
   - 对话框打开后焦点进入内部，`Tab` 焦点不越界，`Escape` 可关闭，关闭后焦点返回触发元素。
   - 不可逆操作的默认焦点应落在较安全的动作上，并必须提供可见关闭方式。
9. [W3C WAI-ARIA：Landmarks 模式](https://www.w3.org/WAI/ARIA/apg/patterns/landmarks/)
   - 使用语义化 `header`、`nav`、`main` 标记全局结构，帮助键盘和辅助技术快速定位。

## 对本项目的设计结论

### 1. 导航按运营任务分组

- **业务履约**：业务概览、订单审核、售后处理。
- **商品运营**：商品与库存、内容运营、商城模板。
- **会员增长**：会员管理、动态规则。
- **平台治理**：账号权限、审计日志、系统配置。
- 保持一级路由和权限码不变，只调整导航呈现、分组和页面元数据。

### 2. 列表统一为五段式

1. 页面标题与唯一主操作。
2. 快捷状态/统计摘要（仅展示能帮助决策的数据）。
3. 搜索筛选区：常用条件常显，高级条件展开，具备查询与重置。
4. 数据表：关键识别字段在左、状态与时间居中、行操作在右；次要操作进入菜单。
5. 批量操作条与分页：仅选择数据后出现批量条，明确数量和影响。

### 3. 详情与处理分离但保持上下文

- 订单、售后、会员、商品采用右侧详情抽屉；保留列表筛选、页码和滚动位置。
- 抽屉标题显示对象标识和状态；主体按“基础资料—业务明细—时间线/审计”分组。
- 当前状态允许的操作放在固定底部操作栏；审核、发货、库存调整等操作再打开结构化业务对话框。

### 4. 表单与危险操作

- 新建/编辑根据字段规模使用弹窗或独立工作区，字段分组并提供行内校验。
- 删除、停用、拒绝、重置密码、角色与账号变更使用统一确认对话框，显示目标、影响、原因、必要的当前密码和提交状态。
- 全部移除浏览器原生 `prompt`、`confirm`、`alert`；成功使用非阻断通知，失败保留输入并聚焦错误。

### 5. 响应式原则

- 桌面端保持中等信息密度和稳定列宽；窄屏把筛选折叠为面板、表格降级为关键字段列表卡，但不删除操作。
- 抽屉在桌面从右侧出现，窄屏占满视口；固定操作栏必须避开内容滚动区。
- 交互不依赖 hover，焦点样式和按钮文字始终可见。

## 暂不采用

- 不在本轮引入完整 UI 框架，以免与现有 Vue 组件、样式和构建体积发生大规模耦合。
- 不把全部详情改成独立路由；高频审核需要保留列表上下文。
- 不使用商城用户端的实验性排版与重动效；后台优先效率、可预期性和审计安全。

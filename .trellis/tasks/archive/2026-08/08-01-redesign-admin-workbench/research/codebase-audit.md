# 后台代码与业务流程审计

## 总览

- 后台共 11 个受保护一级页面，路由、侧栏和默认权限落点分别维护于 `main.ts`、`App.vue`、`session.ts`，已经发生结构重复。
- 全局共享层只有分页、素材、富文本和模板预览；11 个页面重复标题区，17 个模态遮罩自行实现。
- 源码存在 26 个浏览器原生交互调用：21 个 `prompt`、4 个 `confirm`、1 个 `alert`。
- 当前 9 个后台测试主要做源码字符串回归，没有组件挂载、键盘焦点、交互状态和 API 错误分支测试。

## P0：先修复的正确性与安全问题

1. **跨对象旧数据泄漏**
   - `AfterSalesView.vue` 切换详情时未先清空凭证，请求失败会把上一售后单的凭证留在新对象下。
   - `CatalogView.vue` 的库存流水存在相同问题。
   - 打开对象时必须先清空关联数据，以对象 ID 或请求序号拒绝过期响应，并展示局部加载/错误状态。
2. **商品保存与库存调整部分提交**
   - 商品 PUT 成功后才用原生弹窗询问库存原因；取消或库存接口失败时，商品已经生效但界面表现像一次失败/取消。
   - 商品资料保存与库存调整必须拆成两个明确业务动作；库存操作展示当前值、目标值、差值、原因和稳定请求号。
3. **规则加载失败后可用默认值覆盖线上配置**
   - `SettingsView.vue` 加载或解析 `ORDER_TIMERS` 失败时仍保留可提交的默认值。
   - 策略必须明确区分未加载、加载中、已加载、失败；只有读取当前版本成功后才允许编辑和发布。
4. **账号秘密字段输入与生命周期不合格**
   - 当前密码、临时密码通过明文 `prompt` 输入；创建账号表单关闭/成功后也不清理密码字段。
   - 敏感操作统一使用密码输入框，关闭、成功、对象切换时清除秘密字段，禁止持久化。

## P1：高频操作流问题

- 订单/售后可直接在列表通过或拒绝，而详情内没有处理操作，容易绕过凭证、明细和时间线核对。
- 批量发货由三次 prompt 组成，物流号由内部 ID 拼接，部分失败后仍清空全部选择。
- 弹窗内提交失败时，错误常显示在遮罩后方；大量动作缺少独立提交状态与重复提交保护。
- 规则发布把校验和正式发布连成一次提交，没有字段差异、影响说明和最终确认。
- 内容保存与发布耦合；删除内容/共享素材没有展示引用与影响。
- 模板编辑没有脏状态与离开保护，页面文案会让运营人员误以为本地改动已经保存。
- 账号创建入口被角色管理权限误控；部分动作在输入二次验证信息后才收到后端无权错误。
- 筛选表单没有区分草稿条件和已应用条件，订单/审计导出可能使用尚未查询的新条件。

## P2：一致性与布局问题

- 侧栏直到 800px 才收起且自身不可滚动；801–1000px 内容区被显著压缩。
- 页面断点、弹窗宽度、详情结构、状态色和操作列分别实现；窄屏主要退化为横向滚动。
- Dashboard 首屏失败时错误也被 `v-if="data"` 隐藏，最终呈现空白。
- 模板工作室在窄屏仍为编辑栏加预览双列，但隐藏设备切换，实际不可操作。
- 商品页同时承载分类、商品、SKU、库存、素材、富文本；账号页同时承载账号、角色和权限；系统配置与规则页重复编辑订单时限。

## 目标信息架构

1. **工作台**：业务概览。
2. **交易履约**：订单审核、售后处理。
3. **商品运营**：商品与库存、内容运营、商城模板。
4. **会员增长**：会员管理、动态规则。
5. **平台治理**：账号权限、审计日志、系统配置。

路由路径与权限码保持不变，由单一 typed navigation registry 派生路由、侧栏、面包屑和默认落点。

## 目标交互骨架

- **列表**：标题/指标 → 常用筛选与高级筛选 → 已应用条件 → 表格/窄屏摘要卡 → 分页。
- **详情处理**：桌面右侧宽抽屉、窄屏全屏 sheet；包含摘要、明细、凭证/流水、时间线，底部固定合法操作。
- **业务动作**：对象与当前状态 → 目标状态与影响 → 业务字段 → 原因 → 必要时再认证 → 提交状态 → 服务端权威刷新。
- **批量动作**：选择预检 → 逐项核对 → 确认 → 进度 → 成功/失败分组，失败项保留重试。
- **草稿发布**：编辑 → 保存草稿 → 预览/校验 → diff → 发布确认；离开时检查未保存修改。

## 建议实施顺序

1. 基础层与 P0 正确性：设计令牌、导航清单、工作台壳层、Dialog/Drawer/Filter/Table/State 原语、API 错误类型、4 项 P0 修复。
2. 高频履约：Dashboard、订单、售后、会员、审计，建立统一列表—详情—处理模式。
3. 运营与治理：商品、内容、规则、账号、设置、模板，完成草稿发布、敏感操作和窄屏工作室。

# 重设计后台运营工作台布局与操作流程

## Goal

把当前后台从以接口和表单为中心的页面，重构为符合商城运营人员心智模型的工作台：信息层级清晰、常用操作路径短、危险操作可确认、复杂编辑可分步完成，并在桌面端与窄屏设备上保持一致、可靠的使用体验。

## What I already know

- 用户认为后台多个页面的操作逻辑和页面布局不够合理，需要系统性重新设计，而不是只做局部换色。
- 后台已经覆盖仪表盘、订单、售后、商品、内容、模板、规则、会员、账号权限、审计和系统配置。
- 现有业务 API、Sa-Token 权限和服务端状态机应继续作为权威来源。
- 本任务需要先审计现有信息架构与操作链路，再确定统一设计系统和分阶段落地范围。
- 路由、侧栏和默认权限落点存在三份重复定义；11 个页面重复标题区，17 个弹窗自行实现。
- 后台仍有 26 个浏览器原生交互调用，且缺少统一焦点管理、动作级错误和重复提交保护。
- 审计发现 4 项必须先修复的正确性/安全问题：售后凭证与库存流水旧数据串单、商品与库存部分提交、规则加载失败后可用默认值覆盖线上版本、账号密码字段输入与清理不合格。

## Confirmed Decisions

- 保留现有后端接口、权限码和业务状态机，优先重构前端信息架构与交互层。
- 桌面端是后台主要使用场景，同时保证平板和窄屏可操作，不把后台改造成纯移动端应用。
- 统一替换零散的浏览器 `prompt`、`confirm`、`alert`，使用可校验、可加载、可回退的业务弹窗或抽屉。
- 视觉方向保持简洁、专业、中文运营后台风格，不追求商城用户端的实验性动效。
- 采用现代中等信息密度：桌面端强调扫描与批量操作，详情与表单适度留白，窄屏保证完整操作能力。
- 在现有 Vue 3 技术栈内建立轻量、可测试的后台组件层，不引入完整第三方 UI 框架。
- 用户确认完成全后台范围，并要求后续无人值守自动执行。

## Open Questions

- 无。

## Requirements (evolving)

- 建立单一 typed navigation registry，由其派生路由、分组侧栏、面包屑和首个可访问页面。
- 重整全局导航、页面标题、面包屑、筛选区、数据区和操作区的层级；工作台按履约、商品、会员增长和平台治理分组。
- 为列表、详情、编辑、审核、批量处理、危险操作建立统一交互模式；详情在桌面使用右侧抽屉，窄屏使用全屏 sheet。
- 减少跳页和重复输入，操作完成后刷新服务端权威状态并提供明确反馈。
- 统一加载、空状态、错误、权限不足、重复提交和窄屏布局。
- 保持现有中文化、权限控制、凭证安全、模板编辑和富文本安全约束。
- 移除全部原生 `prompt`、`confirm`、`alert`，敏感操作必须显示目标、影响、原因、密码再认证和提交状态。
- 筛选区分编辑中的条件与已应用条件，查询后同步 URL；导出只使用已应用条件。
- 修复跨对象旧数据、部分提交、配置加载失败仍可发布和秘密字段残留问题。
- 订单/售后从“列表直接改状态”调整为“查看并处理”；批量发货提供预检、逐项核对和部分失败重试。
- 内容与规则采用草稿/校验/差异/发布确认链路；模板编辑具备未保存提示和离开保护。
- API 客户端保留 HTTP status、业务 code 和 message，支持 401/403/409 的一致处理。

## Acceptance Criteria (evolving)

- [x] 后台所有一级页面使用统一工作台框架、标题区和响应式内容容器。
- [x] 高频列表支持清晰的筛选、重置、分页、批量操作和行级主次操作。
- [x] 订单、售后、商品和会员详情以结构化抽屉或详情页展示完整上下文。
- [x] 所有浏览器原生 `prompt`、`confirm`、`alert` 被业务组件替代。
- [x] 危险操作显示对象、影响、原因输入、二次校验及提交状态。
- [x] 售后凭证和库存流水不会在对象切换、请求失败或过期响应时串到其他对象。
- [x] 商品资料保存与库存调整是两个独立、可解释、可重试的动作，不产生界面假成功。
- [x] 当前规则版本加载失败时禁止编辑/发布，发布后重新读取并显示服务端版本。
- [x] 账号密码字段始终遮罩，弹窗关闭、成功和对象切换后立即清除。
- [x] 订单和售后详情底部只呈现当前状态及权限允许的处理动作，成功后同步刷新列表与详情。
- [x] 筛选、分页和工作台深链可刷新、返回和分享；导出条件与已查询结果一致。
- [x] 对话框具备语义、焦点圈定、Escape、关闭后焦点恢复和提交期间关闭保护。
- [x] 桌面与窄屏布局均可完成核心业务流程，不依赖 hover。
- [x] 权限、状态机、API 数据和审计要求保持不变。
- [x] 前端测试、类型检查和生产构建通过。

## Definition of Done

- 关键操作流程具备可执行的页面和组件实现，不只输出设计稿。
- 组件、设计令牌和交互约束形成可复用规范。
- 自动化测试覆盖导航、权限、弹窗、列表与关键操作回归。
- `pnpm test:web`、`pnpm typecheck:web`、`pnpm build:web` 全部通过。
- 变更说明、迁移策略和回滚方式写入任务验收记录。

## Out of Scope (temporary)

- 改写后端业务状态机、数据库模型或新增在线支付能力。
- 更换 Vue 3、Vite、Vue Router、Sa-Token 或现有 API 协议。
- 创建独立原生 App。

## Decision (ADR-lite)

**Context**：后台已有完整业务能力，但信息架构、页面状态、详情处理和敏感操作由各页面重复实现；简单换皮会继续放大漂移与正确性风险。

**Decision**：保留现有 API、权限码、Vue 3 和业务状态机，建立单一导航注册表、语义化设计令牌与轻量共享组件层；按“基础/P0 → 高频履约 → 运营治理”三阶段迁移全部后台页面。

**Consequences**：改动面较大，但可在不迁移后端协议的前提下统一交互、响应式与测试边界；领域状态和请求编排仍留在业务页面，避免形成万能 CRUD 抽象。

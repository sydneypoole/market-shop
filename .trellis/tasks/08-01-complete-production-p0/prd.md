# 完成商城生产级 P0 闭环

## 背景

商城已经具备会员端、后台端、线下收款订单、分销规则、模板、凭证、售后、Docker 单镜像和 CI 基线，但审计发现若干会直接阻断交易、造成越权会话、错误发布规则或破坏生产可恢复性的 P0 缺口。本任务只处理 P0，保持 DDD / 凤凰架构依赖方向，所有业务状态与规则以服务端为权威来源。

## 目标

1. 统一订单状态契约，真实跑通“提交订单 → 上传线下付款凭证 → 直属上级确认 → 后台审核 → 发货 → 用户收货”。
2. 让会员与管理员的停用、锁定、重置密码、角色撤销立即使旧会话失效；生产 Cookie 和跨站修改请求满足安全基线。
3. 规则版本加载或解析失败时锁定发布，绝不以本地默认值覆盖线上版本。
4. 为 outbox 建立退避、最大重试、死信、可观测与人工重放闭环，并固化订单完成时适用的规则版本。
5. 提供安全的生产配置、真实 readiness、诊断端点隔离、镜像 digest 发布/回滚与数据库/文件备份恢复流程。
6. 增加真实 API 业务 E2E 发布门禁，覆盖会员、订单、凭证、后台审核发货、收货、分销投影、售后、模板和两种对象存储路径中的关键生命周期。

## 范围与验收标准

### A. 订单状态与交易主链路

- `PENDING_SUPERIOR` 是后端、后台、商城、统计、凭证策略及测试的唯一待上级确认状态值；仓库不再出现历史待确认别名。
- 买家和直属上级在正确状态看到正确操作；未知状态只读展示且不暴露动作。
- API E2E 使用两个会员会话和一个管理员会话断言每一步 HTTP/数据库状态以及库存从预占到消耗的变化。

### B. 账号与会话安全

- 微信登录与开发登录均拒绝 `LOCKED`/`DISABLED` 会员。
- 后台修改会员为非 ACTIVE 后，旧会员 token 下一次请求立即失效；恢复 ACTIVE 后只能重新登录。
- 管理员停用、锁定、重置密码或角色调整后，目标管理员的旧会话立即失效，不能继续使用缓存权限。
- 登录响应不向 JavaScript 暴露 token；Cookie 在生产配置下包含 `HttpOnly`、`Secure` 和 `SameSite=Lax`（本地 HTTP 仍可开发）。
- 浏览器跨站发起的修改请求被 Origin 校验拒绝；同源及无 Origin 的可信非浏览器调用按契约处理。

### C. 规则编辑安全

- 将“列表加载成功”“当前版本存在”“当前版本解析/校验成功”分开建模。
- 服务端已有当前版本但 JSON 损坏、不是对象或缺关键字段时，编辑与发布保持锁定并展示可恢复错误。
- 仅在服务端明确不存在首版时允许初始化安全默认值。
- 前端测试覆盖非法 JSON、数组、缺字段、空版本及发布后回读失败。

### D. Outbox 与规则快照

- 订单完成事务固化本次投影采用的规则版本 ID；延迟期间发布新规则不改变旧订单的升级、奖励、冻结/释放计算。
- 投影失败增加 attempt、记录截断后的 last_error、指数退避；达到上限进入 `DEAD`，后续事件仍可继续。
- 失败状态更新使用独立事务，不与失败的业务投影一起回滚。
- 提供受权限保护的死信查询/重放入口或等价运维命令，重放操作可审计；提供 pending oldest-age/dead 指标。
- 数据库/应用测试注入毒事件与有效事件，断言毒事件最终死信且有效事件被处理；测试规则切换期间的历史快照。
- 同一直属上级的并行投影在计算完成序号前锁定上级稳定会员行；序号唯一且连续，第 6 笔奖励不漏发，重放不重复计数或发奖。

### E. 生产运行、健康、备份与发布

- `docker-compose` 默认生产 profile；local/mock/bootstrap 只能显式开启。MySQL 与 Redis 默认不发布宿主机端口，开发需要时仅绑定 `127.0.0.1`。
- 新增生产配置 fail-fast：占位/开发密钥、启用 mock、HTTP OAuth 回调或缺关键凭据时拒绝启动。
- 登录页不预填管理员密码；生产环境不展示开发登录入口/开发凭据。
- readiness 明确包含 MySQL、Redis、当前对象存储；外部依赖中断时 readiness DOWN，liveness 仍反映 JVM 进程状态。
- 公网 Nginx 仅暴露无详情健康端点，Swagger/OpenAPI/Actuator 诊断端点不公开。
- 备份同时覆盖 MySQL 与本地上传/RustFS 数据，包含校验清单、保留与加密/异地复制接口；恢复脚本对空环境恢复并执行 Flyway/对象摘要/smoke 校验。
- 提供以镜像 digest 晋级、部署前备份和迁移预检、健康切流、上一 digest 回滚的脚本和中文运维文档；迁移失败不得切流。
- 文档定义 RPO 不高于 15 分钟、RTO 不高于 2 小时及恢复演练步骤。

### F. 发布门禁

- 后端单元/集成测试、前端测试/typecheck/build、Docker 空库 smoke、业务 API E2E 全部通过。
- local 文件存储及 RustFS/S3 适配器的上传、授权读取、过期/删除关键链路至少各有一条真实控制器/适配器验证。
- `git diff --check` 通过；新增行为同步到 `.trellis/spec/`。

## 非目标

- 本任务不处理审计中标为 P1/P2 的服务端分页、审计 reason 全链路、售后并发唯一约束、所有页面脏状态保护、可访问性全面改造或性能容量优化；若 P0 测试暴露阻断性依赖，仅做最小必要修复。
- 不引入在线支付、提现、跨级分销或多级返佣。

## 架构约束

- Domain 保持框架无关；Application 定义会话失效、规则快照和投影运维所需端口；Infrastructure 实现持久化与调度；Interfaces 处理 HTTP、Sa-Token、Cookie、Origin 和 RBAC。
- Flyway 只前向新增迁移，不改已发布脚本；钱以分为单位；规则版本不可变，订单/证据保留版本引用。
- 所有敏感操作沿用统一错误码、审计和权限体系；日志不输出 token、密码、密钥或完整凭证 URL。

### 身份收尾契约

- 会话建立时写入数据库返回的 `auth_epoch`；每个会员/管理员请求（包括
  `auth/me`）都重新读取账号状态与 epoch，失配立即注销当前 Sa-Token 会话。
- OAuth state 必须一次性消费并与 HttpOnly 浏览器绑定值一致；回跳只允许已配置
  storefront origin 的相对路径。发起人认领密钥独立于普通邀请码，不能以明文或裸
  hash 写入日志/Redis，且 `WECHAT_MOCK` 身份不得走认领路径。
- 管理员失败计数在数据库单条更新中封顶；并发到达阈值只提升一次 epoch，锁过期后
  下一次失败从 1 重新计数。登录成功在清零失败计数后重读账号，避免并发停用/改密
  把新会话初始化为旧 epoch。首次强制改密保留当前浏览器并切换到新 epoch。

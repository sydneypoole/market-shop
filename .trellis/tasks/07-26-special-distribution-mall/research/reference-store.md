# 参考 H5 功能地图

调研时间：2026-07-26

参考地址：<https://shop.xingkehui.com.cn/h5/#/pages/index/index>

## 已观察页面

### 首页

- Banner / 品牌视觉内容。
- 公告入口。
- 快捷入口：品牌介绍、报单专区、百问百答、发圈素材、商学院。
- 推荐商品双列瀑布流。
- 底部导航：首页、商品分类、购物车、我的。

### 商品分类

- 商品搜索。
- 左侧分类：升级、复购。
- 商品列表展示图片、名称、现价、划线价和加入购物车动作。
- 示例商品体现不同会员档位/身份商品。

### 购物车

- 未登录时展示空购物车和登录入口。
- 目标商城应补足：勾选、数量变更、失效商品、价格重算、结算、库存校验。

### 会员中心

- 账户摘要：余额、积分、优惠券。
- 订单入口：全部、待付款、待发货、待收货、待评价。
- 推广中心：二维码、我的客户。
- 其他功能：个人资料、收货地址、关注、足迹。

### 认证

- 登录：账号 + 密码、忘记密码。
- 注册：邀请码、+86 手机号、密码、确认密码、图形验证码、短信动态码、注册协议。
- 邀请码是注册主链路的一部分，适合承载可审计的邀请关系绑定。

## 可借鉴与需改进

- 借鉴信息架构和功能范围，不复制品牌、文案、图片、样式或专有素材。
- 参考站首页在调研时出现 `ReferenceError: colorList is not defined`，说明首页配置必须使用有默认值的类型化契约，客户端不能依赖未声明的全局变量。
- 参考站将“升级商品”和“复购商品”分开；目标系统应将其建模为商品标签/销售场景，避免商品实体与会员等级强耦合。
- 参考站把“余额”和“积分”并列展示；目标系统必须区分现金钱包、不可提现积分、奖励积分等账户类型，并为每种账户建立独立流水与可用性规则。

## 建议的目标端

- Storefront：一套 Vue 3 + Vite + TypeScript 响应式应用，同时覆盖桌面网页和 H5。
- Admin：独立 Vue 3 + Vite + TypeScript 运营后台。
- 后端统一 REST API，使用 OpenAPI 生成 TypeScript 客户端类型。
